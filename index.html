🌎 Active Directory Concepts — Lay of the Land ▼
Core Components
ComponentWhat It IsWhy It Matters in a Pentest
Domain Controller (DC) Server that hosts the AD database. Handles Kerberos authentication (KDC), LDAP queries, and replication. The primary target. Owning a DC = owning the domain. Find it via DNS (port 53) or ipconfig /all — the DNS server is almost always the DC.
NTDS.dit The AD database file on every DC (C:\Windows\NTDS\ntds.dit). Stores all objects: users, computers, groups, and all password hashes (NT hashes + Kerberos keys). The crown jewels. Dumping it via DCSync or VSS gives you every hash in the domain.
SYSVOL A folder replicated across all DCs (\\domain\SYSVOL). Contains GPO templates, login scripts, and policy files. Often contains scripts with hardcoded credentials. Always spider it with valid creds.
LSASS (lsass.exe) Local Security Authority Subsystem. Handles logins and caches credentials in memory for SSO. Dumping LSASS gives you plaintext passwords (if WDigest on), NT hashes, and Kerberos tickets for all logged-in users.
SAM Database Local account database on non-DC machines (C:\Windows\System32\config\SAM). Stores local user NT hashes. Dump with reg save or secretsdump. Local admin hash reuse across many machines is a very common path for lateral movement.
krbtgt account Built-in service account whose hash is used by the KDC to sign all Kerberos TGTs. If you have this hash → Golden Ticket → unlimited persistence. Resetting it requires two password changes to fully invalidate existing tickets.
Directory Structure
TermDefinitionPentest Relevance
Forest The top-level security boundary in AD. Contains one or more domains. All domains in a forest share the same schema and global catalog. Compromise the forest root domain → Enterprise Admin → full forest control. Forest is the real boundary, not the domain.
Domain Administrative and authentication boundary. All objects (users, computers, groups) belong to a domain and share its policies and database. Your primary scope. Domain Admin = full control of that domain but NOT other domains in the forest unless trusts exist.
Tree A group of domains with a contiguous DNS namespace (e.g., corp.local → dev.corp.local). Parent and child domains have automatic two-way transitive trusts. Child domain compromise → parent domain via SID History or trust abuse in many configurations.
Organizational Unit (OU) A container within a domain used to organise objects (users, computers). GPOs are linked to OUs. Admins can be delegated control of specific OUs. If you have write access to a GPO linked to an OU containing DCs → code execution on all DCs.
Site Represents physical network topology. Used to control Kerberos authentication routing and DC replication schedules. Mostly informational. Useful when scoping reachable DCs across subnets.
Global Catalog (GC) A DC that holds a partial read-only copy of all objects across all domains in the forest. Listens on ports 3268/3269. Query the GC to enumerate users/groups across the entire forest, not just the current domain.
Authentication — Kerberos (the default)
TermDefinitionAttack Relevance
TGT (Ticket Granting Ticket) A ticket issued by the KDC after successful login. Proves your identity. Encrypted with the krbtgt hash — only the KDC can read it. Valid for 10 hours by default. Steal a TGT → authenticate as that user without knowing their password. Pass-the-Ticket. Forge one with krbtgt hash → Golden Ticket.
TGS (Ticket Granting Service) A service ticket issued by the KDC when you want to access a specific service. Encrypted with the service account's hash. The TGS is encrypted with the service account's NT hash → you can request one for any SPN and crack it offline → Kerberoasting. Forge one with service hash → Silver Ticket.
Pre-authentication Before the KDC issues a TGT, the client proves it knows the password by encrypting a timestamp. Default ON for all accounts. Accounts with pre-auth disabled can have their TGT requested by anyone without a password → offline crack → AS-REP Roasting.
SPN (Service Principal Name) A unique identifier that maps a service instance to a service account (e.g., MSSQLSvc/sql01.corp.local:1433). Required for Kerberos service authentication. Any domain user can request a TGS for any SPN → Kerberoasting. If you can add an SPN to an account (GenericWrite) → you can Kerberoast it.
PAC (Privilege Attribute Certificate) Embedded in Kerberos tickets. Contains the user's group memberships, SID, and other authorisation info. Signed by the KDC. MS14-068 (now patched) allowed forging a PAC. Silver Tickets omit the PAC by default — some services don't check it, making forged tickets valid.
Delegation Allows a service to authenticate to another service on behalf of a user. Three types: Unconstrained, Constrained, and Resource-Based Constrained (RBCD). Unconstrained: steal TGTs of any user who authenticates to the service. Constrained/RBCD: impersonate Domain Admin to specific services. See the Delegation technique cards.
Authentication — NTLM (legacy, but everywhere)
TermDefinitionAttack Relevance
NT Hash MD4 hash of the user's password. Stored in SAM (local) and NTDS.dit (domain). This is what secretsdump gives you. Use directly for Pass-the-Hash with impacket, nxc, evil-winrm. Also used as RC4 key in Kerberos (Overpass-the-Hash).
Net-NTLMv1 / Net-NTLMv2 The challenge-response exchange that happens during NTLM authentication over the network. Captured by Responder. Contains the NT hash mixed with a server challenge. Cannot be used for PTH directly. Can be: (1) cracked offline with hashcat, or (2) relayed to another service with ntlmrelayx if SMB signing is disabled. This is the #1 beginner confusion.
NTLM Relay Forward a captured Net-NTLMv2 challenge-response to another host before it times out. The target authenticates you as the victim. Works when SMB signing is disabled (check with nxc smb --gen-relay-list). Combine with coercion (PetitPotam) to force DC authentication → relay to LDAP/ADCS.
LM Hash Legacy, extremely weak predecessor to NT hash. Almost always aad3b435b51404eeaad3b435b51404ee (empty/disabled) on modern systems. Ignore it. Just use the NT hash part. If you see a real LM hash, it means the system is ancient and cracking it trivially gives you the password.
Key AD Object Types
ObjectNotes
User accountHas a SID, SAMAccountName (e.g. jdoe), and UPN (jdoe@corp.local). Password stored as NT hash + Kerberos keys in NTDS.dit.
Computer accountMachine joined to domain. Name always ends with $ (e.g. WS01$). Has its own NT hash (rotated every 30 days). Can be Kerberoasted if it has an SPN.
Security GroupUsed for access control. Three scopes: Domain Local, Global, Universal. Membership defines what resources you can reach.
gMSA (Group Managed Service Account)Service account with an automatically rotated 240-char password managed by AD. Password readable by authorised accounts via LDAP.
GPO (Group Policy Object)A set of policy settings linked to Sites, Domains, or OUs. Applied to all objects in the linked container. Stored in SYSVOL and LDAP.
Access Control Terms (ACLs)
TermDefinition
ACL (Access Control List)Every AD object has one. The list of who can do what to that object.
ACE (Access Control Entry)A single entry in an ACL: "User X has permission Y on this object." BloodHound edges represent abusable ACEs.
DACL (Discretionary ACL)The part of the ACL that controls access. What BloodHound reads and what you abuse.
SACL (System ACL)Controls auditing — what access gets logged in the Security event log. Read-only for attackers; relevant for OPSEC.
SID (Security Identifier)Unique identifier for every security principal (user, group, computer) in AD. Format: S-1-5-21-<domain>-<RID>.
RID (Relative Identifier)Last number in a SID. Well-known RIDs: 500 = Administrator, 502 = krbtgt, 512 = Domain Admins, 519 = Enterprise Admins.
SID HistoryAn attribute that can hold old SIDs from previous domains (used after migrations). If an attacker adds a privileged SID to this field → instant privilege escalation across trusts.

🔇 OPSEC & Noise Guide ▼
Attack Noise Levels
ActionNoiseEvent / DetectionQuieter Alternative
DCSync (secretsdump -just-dc) CRITICAL Event 4662 — DS-Replication-Get-Changes-All. Every SIEM watches for this. VSS shadow copy ntds.dit on DC → secretsdump -ntds ntds.dit -system sys LOCAL
LSASS dump (ProcDump / Task Manager) LOUD Sysmon Event 10 — process access to lsass.exe. EDR triggers immediately. nanodump (direct syscalls), comsvcs MiniDump (slightly quieter), HandleKatz

Zerologon (CVE-2020-1472) CRITICAL Corrupts DC machine account password. Events 4742, 4624. Breaks domain if not restored. Avoid in production. If used, restore machine account password immediately after.
noPac (CVE-2021-42278/42287) LOUD Creates a machine account, renames it — Events 4741, 4781, 4768. Clean up created machine account after exploitation.
nmap full port scan (-p- or -A) LOUD Network IDS SYN-scan signatures. ARP noise. Easy to detect. Targeted port scans (-p 88,389,445,5985,3389), slow timing (-T2)
Password spray MODERATE Spike of 4625 failures across multiple accounts. 1 attempt per lockout window. Check lockout policy first. Off-hours timing.
Kerberoasting (all SPNs) MODERATE Event 4769 — RC4 TGS-REQ. If AES-only policy, RC4 requests are flagged. Request only specific targeted SPNs. Use /etype:aes256 in Rubeus to request AES tickets.
BloodHound collection (All methods) MODERATE Anomalous LDAP query volume — hundreds of 4662 events in seconds. DCOnly collection first. Use stealth or ldap-filter method. Add --loop-delay intervals.
PetitPotam / coercion attacks MODERATE Event 4648 — explicit credential use from DC to attacker IP. Authenticated variant requires creds (less suspicious). Time alongside other activity.
Pass-the-Hash (NTLM lateral) MODERATE Event 4624 Type 3 logon via NTLM from unexpected source host. Overpass-the-Hash → Kerberos TGT. Kerberos blends far better with normal traffic.
AS-REP Roasting LOW Event 4768 with preauth not required. Only caught by targeted SIEM rules. Already low — limit to known preauth-disabled accounts.
LDAP enumeration (with creds) LOW Blends with normal AD traffic. Only caught by anomaly baselining. Already low in most environments.
SMB share spidering LOW File access events on shares if object auditing is enabled. Avoid C$ and ADMIN$ admin shares (commonly audited). Target named shares.
General OPSEC Tips
TipDetail
Identify AV/EDR before dropping toolstasklist /svc | findstr /i "sense defender crowdstrike carbon cylance sentinel" — know what detection is running before executing anything.
AMSI bypass before PowerShell toolsRequired before PowerView, SharpHound PS edition, or any .NET reflective load. Many public bypasses are signatured — use an obfuscated one or a memory-patch variant.
Prefer Kerberos over NTLMOverpass-the-Hash converts an NT hash to a Kerberos TGT — lateral movement then uses Kerberos tickets which are far harder to correlate across hosts than NTLM relay chains.
Use AES, not RC4RC4 is legacy and flagged by many detections (etype:0x17 in event logs). Request AES256 tickets whenever possible (Rubeus /etype:aes256).
Living-off-the-land (LOLBins)Built-in tools blend with normal admin activity: net, nltest, reg, wmic, certutil, dsquery. Prefer these for enumeration before uploading external tools.
Delete tools after useRemove uploaded binaries from disk immediately after use. In-memory execution (reflective load, execute-assembly) is preferred when AV/EDR is present.
Avoid admin shares (C$, ADMIN$)Access to default admin shares is commonly audited. Prefer explicit named shares or WinRM/DCOM for lateral movement.
Blend with business hoursRun noisy operations (scans, BloodHound collection) during business hours when AD activity is expected. 3 AM spikes stand out immediately in logs.

🏭 Kerberos — How It Works & Attack Theory ▼

Kerberos is the default authentication protocol in AD. Every major AD attack (PTH, PTT, Golden Ticket, Kerberoasting, RBCD…) abuses some aspect of it. Understanding the flow is essential for both executing attacks and explaining them in interviews.

Key Concepts
ConceptWhat it isAttacker relevance
TGTTicket Granting Ticket — valid 10 hours by default. Encrypted with krbtgt hash, never readable by the client.Steal via Unconstrained Delegation or memory. Forge with krbtgt hash → Golden Ticket (valid 10 years).
Service TicketIssued per-service (SPN). Encrypted with the service account's hash. Valid 10 minutes by default.Forge with service account hash → Silver Ticket. Requested for any SPN → Kerberoasting (crack offline).
PACPrivilege Attribute Certificate — embedded in tickets. Contains user's SIDs and group memberships. Signed by krbtgt and KDC.Adding extra SIDs (Enterprise Admins) to the PAC enables child→parent forest attacks.
Pre-authenticationClient must prove knowledge of password before getting a TGT by encrypting a timestamp with their hash.Disabled → AS-REP Roasting: KDC returns encrypted blob without proof, crack offline without touching the DC again.
RC4 vs AESRC4 uses the NT hash directly. AES256 uses a key derived from the password.RC4 tickets are easier to crack and more detectable. Request AES tickets with Rubeus /aes256 for stealth.
KRBTGTSpecial service account — its hash encrypts all TGTs in the domain. Never logs in interactively. Password never naturally changes.Obtaining the krbtgt hash = unlimited Golden Tickets. Reset twice to invalidate all forged TGTs.
